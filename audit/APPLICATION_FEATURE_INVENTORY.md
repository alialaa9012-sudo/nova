# جرد التطبيق الكامل: تطبيق طلبات «خليها مشاوي»

تاريخ المراجعة: 16 نوفمبر 2026. الإصدار المراجَع: فرع `ccr-8718d4a1-n447s4` عند الـ commit `5daaad9`.

## 1) ما هو التطبيق ونموذج العمل

- **الغرض:** موقع ويب عربي (من اليمين لليسار) يطلب منه عميل مطعم «خليها مشاوي» أونلاين من أحد ثلاثة فروع: العاشر من رمضان، الزقازيق، التجمع الخامس.
- **نموذج العمل:** الطلب يصل للكول سنتر، الموظف يحدّث حالته من لوحة مركزية ويدخله يدوياً في نظام الكاشير (Crystal Mind). الدفع كاش فقط عند الاستلام. لا حساب للعميل ولا دفع إلكتروني.
- **الجمهور المستهدف:** عملاء المطعم في المدن الثلاث، أغلبهم على الموبايل. والمستخدم الثاني هو موظف الكول سنتر على كمبيوتر أو تابلت.

## 2) حالة النضج الحالية

التطبيق في **الوضع التجريبي (Demo)**: كل الطلبات تُحفظ في متصفح الجهاز نفسه (localStorage) ولا تصل للمطعم. قاعدة البيانات (Supabase/Postgres) مكتوبة ومختبرة محلياً لكنها **غير منشورة ولا مربوطة**، ولا توجد إشعارات Telegram ولا نشر على استضافة حقيقية بعد.

## 3) الشاشات والمسارات

| المسار | الشاشة | المستخدم | الحالة |

## 4) خريطة الرحلات

```
الرئيسية ──اختيار فرع──▶ المنيو ──(+)──▶ نافذة الصنف ──أضف──▶ السلة ──إتمام──▶ إتمام الطلب ──تأكيد──▶ صفحة الطلب
    │                                                                                                   ▲
    ├──تتبع طلب──▶ شاشة التتبع (رقم + موبايل) ───────────────────────────────────────────────────────────┘
    └──واتساب (رابط خارجي)

لوحة الكول سنتر (/admin) ◀── الطلب يظهر فوراً (نفس المتصفح) ──▶ نقل الحالة / إلغاء / تفاصيل / رقم فاتورة
        └── مناطق التوصيل (/admin/zones) ──▶ تظهر للعميل فوراً في إتمام الطلب
```

## 5) الميزات بالتفصيل

### واجهة العميل
- اختيار الفرع، مع حالة «مفتوح حتى…» أو «مغلق، يفتح…» محسوبة بتوقيت القاهرة وتدعم الإغلاق بعد منتصف الليل.
- منيو لكل فرع (منيوان: الأبيض للعاشر والزقازيق، الأسود للتجمع)، 16 قسماً في العاشر، أسعار بأحجام (ربع/تلت/نص/كيلو).
- بحث بالاسم يتسامح مع اختلاف الحروف (كفته = كفتة).
- أصناف الحجز المسبق (كتف/فخدة في التجمع) بزر «احجز» يتصل بالفرع بدل الإضافة.
- ملاحظة اختيارية على كل صنف (حتى 120 حرفاً) تظهر في السلة وللموظف.
- سلة تُحفظ على الجهاز لكل فرع، ومسودة بيانات إتمام الطلب تُحفظ وتُمسح بعد الطلب.
- رسوم توصيل حسب المنطقة، ضريبة 14٪ في التجمع فقط، لا رسوم خدمة.
- حد 3 طلبات لكل رقم موبايل كل 10 دقائق، وحد 50 لكل كمية و40 سطراً للسلة.
- رقم طلب يومي لكل فرع (A-0001، Z-0001، T-0001).
- التتبع متاح لطلبات آخر 3 أيام فقط، وبرقم الموبايل الذي طلب به.
- الفرع المقفول: يقدر العميل يجهز السلة لكن لا يؤكد.

### لوحة الموظفين
- الطلبات الأقدم أولاً في الحالات الجارية، شارة عمر الطلب (عادي/تنبيه من 10 دقائق/عاجل من 20).
- الأصناف وملاحظاتها على الكارت نفسه، والعنوان ورقم العميل قابل للاتصال.
- 4 حالات فقط: جديد، جاري التجهيز، خرج للتوصيل (أو جاهز للاستلام)، ملغي، والإلغاء بسبب إلزامي.
- حقل «رقم الفاتورة في Crystal Mind» لمطابقة الطلب مع الكاشير.
- صوت وتنبيه عند طلب جديد.

### ما هو مبنيّ لكنه مخفي حتى يصل محتوى حقيقي
- بنر الرئيسية وشريط العروض (من `data/promotions.json`، فارغ الآن).
- شارات الأصناف (من `data/menu_extras.csv`، فارغ الآن).
- صور الأصناف (مجلد `menu-images/` فارغ، تظهر أيقونة بديلة).

## 6) البنية التقنية

| الطبقة | ما هو مستخدم |
|---|---|
| الواجهة | React 19، TypeScript 6، Vite 8، react-router 8، Tailwind CSS 4، مكونات shadcn/Radix، أيقونات Lucide، خطوط Cairo وAmiri محلية |
| الحالة | React Context + localStorage (السلة، المسودة، آخر طلب) |
| الخلفية الحالية | `src/lib/api/local.ts`: محاكاة كاملة لقواعد قاعدة البيانات داخل المتصفح |
| الخلفية المستقبلية | Supabase (Postgres): ملف الهجرة `supabase/migrations/20261111120000_init.sql` بـ 13 جدولاً، 4 دوال للعميل والموظف، سياسات RLS كاملة. مختبر بـ PGlite داخل الاختبارات |
| البيانات | ملفات CSV/JSON في `app/data/` تُقرأ وقت البناء (المنيو، المناطق، الفروع، المواعيد) |
| الاختبارات | Vitest (109 اختبار وحدة، تغطية 81٪)، Playwright (40 اختبار متصفح على كروم مكتبي وPixel 7)، axe-core لإمكانية الوصول |
| النشر | لا يوجد بعد. ملف `_redirects` جاهز لـ Cloudflare Pages/Netlify |

### جداول قاعدة البيانات
`branches`، `branch_hours`، `menu_categories`، `menu_items`، `menu_item_sizes`، `delivery_zones`، `app_settings`، `staff_profiles`، `order_counters`، `orders`، `order_items` (مع عمود `note` للملاحظة)، `order_status_history`، `notification_log`.

### الدوال
- للعميل (بدون حساب): `place_order` (تعيد حساب الأسعار من القاعدة ولا تثق بالمتصفح)، `track_order`، `branch_is_open`.
- للموظف (بحساب): `set_order_status`، `set_pos_invoice`.

## 7) التكاملات الخارجية
- **واتساب:** رابط `wa.me` فقط (لا API).
- **خرائط Google:** رابط مشاركة لكل فرع.
- **Telegram:** جدول `notification_log` جاهز، لكن لا يوجد كود إرسال.
- **Crystal Mind (الكاشير):** لا ربط؛ حقل يدوي لرقم الفاتورة.
