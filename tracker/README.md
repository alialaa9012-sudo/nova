# Daily Tracker

بوت تليجرام شخصي لمتابعة المهام والعادات والتقدّم اليومي.

مستخدم واحد فقط (allowlist بمعرّف تليجرام)، رسالة "اليوم" واحدة تُحدَّث في مكانها،
وتذكيرات تنجو من إعادة النشر لأنها مخزّنة في قاعدة البيانات لا في الذاكرة.

## ما يفعله

| | |
|---|---|
| **المهام** | ثابتة أو متكررة (يومي / أيام محددة / أسبوعي)، إنجاز بلمسة، ترحيل غير المنجز |
| **العادات** | أربع عادات بحدّين لكل واحدة: حدّ الإنجاز وحدّ التميّز |
| **القاموس** | كل جملة إنجليزية تكتبها تُحفظ، وتُراجَع معك آخر الأسبوع |
| **الأحداث** | حدث بتاريخ ووقت، وتذكير قبله بمهلة تختارها |
| **المراجعة** | كل ليلة: ما تمّ، ما فات، ترحيل، وتقييم مزاج |
| **التقارير** | أسبوعي وشهري بترتيب العادات ومقارنة بالفترة السابقة |

التقدّم يُعرض دائماً **كرقمين منفصلين** — نسبة المهام ونسبة العادات — ولا يُدمجان في رقم واحد.

## الأوامر

| الأمر | الوظيفة |
|---|---|
| `/today` | رسالة اليوم |
| `/note` | ملخص سريع لليوم |
| `/review` | مراجعة اليوم عند الطلب |
| `/event` · `/events` | إضافة حدث · الأحداث القادمة |
| `/dict` | قاموس الجمل الإنجليزية |
| `/week` · `/month` | ملخص الأسبوع · الشهر |
| `/times` | مواعيد الرسائل (أو اكتب «مواعيد») |
| `/pause` · `/resume` | إيقاف الإشعارات · تشغيلها |
| `/export` | تصدير كل بياناتك JSON و CSV |
| `/cancel` | إلغاء ما ينتظره البوت منك |

أي **نص عادي** يتحوّل إلى مهمة: `كل سبت جيم 6م` → مهمة اسمها "جيم"، كل سبت، الساعة ٦ مساءً.

## التقنيات

| الطبقة | التقنية |
|---|---|
| البوت | aiogram 3 |
| الويب / webhook | FastAPI + uvicorn |
| القاعدة | PostgreSQL (Neon) — وSQLite محلياً |
| ORM والهجرات | SQLAlchemy 2.0 async + Alembic |
| الجدولة | جدول `reminders` + نبضة خارجية على `/cron/tick` |

## التشغيل محلياً

```bash
python3 -m pip install -r tracker/requirements-dev.txt
cp tracker/.env.example tracker/.env      # ثم املأ القيم
cd tracker && python -m alembic upgrade head && cd ..
uvicorn tracker.app:app --reload
```

مع `DATABASE_URL=sqlite+aiosqlite:///./local.db` تعمل بلا أي خادم قواعد بيانات.

## الاختبارات

```bash
python3 -m pytest tracker/tests -q
```

٢٦٠ اختباراً، ولا واحد منها يلمس الشبكة: تليجرام يُحاكى بجلسة تسجّل ما كان
سيُرسل (`tracker/tests/fake_telegram.py`)، والقاعدة SQLite في الذاكرة.

## النشر على Render (الطبقة المجانية)

1. **اربط الريبو**: من Render اختر New → Blueprint وأشر إلى `render.yaml`.
2. **اضبط الأسرار** من لوحة Render (Environment):
   - `BOT_TOKEN` — من BotFather
   - `ALLOWED_USER_ID` — معرّفك من `@userinfobot`
   - `DATABASE_URL` — رابط Neon
   - `PUBLIC_URL` — عنوان الخدمة بعد أول نشر، مثل `https://daily-tracker.onrender.com`
   - `WEBHOOK_SECRET` و`CRON_SECRET` يولّدهما Render تلقائياً
3. **أعد النشر** بعد ضبط `PUBLIC_URL` حتى يُسجَّل الـwebhook.
4. **فعّل النبضة**: أنشئ مهمة على [cron-job.org](https://cron-job.org) كل دقيقة على:
   `https://<your-service>.onrender.com/cron/tick?key=<CRON_SECRET>`

### لماذا النبضة الخارجية ضرورية

خدمة Render المجانية تتوقف بعد ١٥ دقيقة بلا حركة، وتحتاج نحو دقيقة لتستيقظ.
النبضة تبقيها مستيقظة وتُنفّذ التذكيرات المستحقة في آنٍ واحد، فأقصى تأخير
في أي تذكير دقيقة واحدة — ولا يضيع تذكير أبداً لأن الطابور في القاعدة.

النبضة آمنة للتكرار: ما أُرسل يُعلَّم فلا يُرسل مرتين، وتوليد تذكيرات
الأيام القادمة عملية idempotent.

> ⚠️ لا تستخدم قاعدة Postgres المجانية على Render: تُحذف بياناتها بعد ٣٠ يوماً.
> استخدم Neon (بلا تاريخ انتهاء) كما في الإعداد أعلاه.

## الأمان

- الأسرار من متغيّرات البيئة فقط — لا شيء منها في الكود أو Git.
- `/webhook` يتحقق من `X-Telegram-Bot-Api-Secret-Token`.
- `/cron/tick` يتحقق من `CRON_SECRET`.
- أي تحديث من غير `ALLOWED_USER_ID` يُتجاهل بصمت، قبل فتح أي جلسة قاعدة بيانات.
- خطأ في أي معالج يُسجَّل ويُبلَّغ للمستخدم بدل أن يُسقط الـwebhook — وإلا
  أعاد تليجرام إرسال نفس التحديث في حلقة لا تنتهي.

## بنية المشروع

```
tracker/
├── bot/
│   ├── handlers/        today · habits · events · review · schedule · reports · admin
│   ├── keyboards.py     لوحات الأزرار وبيانات النداءات
│   └── middlewares.py   allowlist + جلسة القاعدة لكل تحديث
├── services/            منطق العمل — مستقل تماماً عن aiogram وFastAPI
│   ├── timeutil.py      اليوم المنطقي وحدوده الأسبوعية والشهرية
│   ├── tasks.py         التكرار، التوليد، الترحيل
│   ├── habits.py        العتبات، السلاسل، القاموس
│   ├── scheduling.py    بناء طابور التذكيرات
│   ├── reminders.py     تنفيذ المستحق
│   ├── progress.py      تجميع فترة
│   ├── parsing.py       قراءة النص العربي الحر
│   └── render.py        بناء نصوص الرسائل
├── db/
│   ├── models.py        نماذج SQLAlchemy
│   └── migrations/      Alembic
├── app.py               FastAPI: /webhook + /cron/tick + /health
└── tests/
```

طبقة `services/` لا تستورد aiogram ولا FastAPI، فكل منطق العمل قابل
للاختبار بلا بوت ولا خادم.

## ملاحظتان عن الوقت

**اليوم المنطقي** لا يبدأ من منتصف الليل بل من الساعة ٤ فجراً
(`day_boundary_hour`). لذلك المراجعة الليلية الساعة ١٢:٠٠ تُراجع اليوم الذي
انتهى للتو، ومن سهر بعد منتصف الليل يظل يسجّل على يوم أمس.

**المواعيد بيانات لا كود**: كل تغيير يكتب صفاً جديداً في `schedules` ويعيد
جدولة ما لم يُرسَل بعد. البوت يسأل عن مواعيد الأسبوع الجاي مع مراجعة ليلة
الجمعة، فلا تحتاج أن تتذكّر تغييرها بنفسك.
