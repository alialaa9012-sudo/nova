# خريطة الموقع ونطاق الفحص

تاريخ الاكتشاف: 19 نوفمبر 2026. كل ما هنا مقروء من الكود وقاعدة البيانات **قراءةً فقط**.

## التقنيات (مكتشفة، لا مفترضة)

| الطبقة | التقنية |
|---|---|
| الواجهة | React 19 + TypeScript، Vite 8، react-router 8، Tailwind 4، مكونات Radix (shadcn)، أيقونات Lucide، رسائل sonner |
| الخطوط | Cairo وAmiri، ملفات محلية (fontsource) |
| الخلفية | Supabase: قاعدة Postgres 17 (فرانكفورت)، PostgREST، Auth (إيميل وكلمة سر)، Realtime |
| الاستضافة | Cloudflare Pages، المشروع `khaliha-mashawy`، يُبنى تلقائياً من فرع العمل على GitHub |
| الرابط الحالي | `https://khaliha-mashawy.pages.dev` (لا يوجد دومين خاص بعد) |
| وضع تجريبي | نفس الكود بدون قاعدة بيانات (الطلبات في المتصفح)، يُستخدم في الاختبارات ونسخة الـ Artifact |

حجم الكود: حوالي 5,855 سطر في `app/src` (بدون الاختبارات)، و1,769 سطر اختبارات وحدة، و6 ملفات اختبارات متصفح.

## الصفحات والمسارات

| # | المسار | الصفحة | من يستخدمها |
|---|---|---|---|
| 1 | `/` | الرئيسية: اختيار الفرع، اتصال، خريطة، شريط سفلي (موبايل)، رابط «طلبك …» | العميل |
| 2 | `/branch/:branchId` (ashry، zagazig، tagamoa) | المنيو: بحث، شريط أقسام، كروت، نافذة الصنف، السلة | العميل |
| 3 | `/branch/:branchId/checkout` | إتمام الطلب: توصيل/استلام، بيانات، منطقة، عنوان، ملاحظات، تأكيد | العميل |
| 4 | `/order/:number` | صفحة الطلب: الرقم، نسخ ومشاركة، خط الحالة، التفاصيل، اطلب مرة أخرى | العميل |
| 5 | `/track` | تتبع طلب برقمه ورقم الموبايل | العميل |
| 6 | `/admin` | لوحة الكول سنتر: فلاتر الفرع والتاريخ والبحث والحالة، كروت الطلبات، نقل الحالة، الإلغاء بسبب، التفاصيل، رقم فاتورة الكاشير | موظف / مدير |

نوافذ تُفحص كشاشات مستقلة: نافذة الصنف، السلة، تفاصيل الطلب (لوحة)، الإلغاء (لوحة)، شاشة دخول الموظفين.

## الأدوار والصلاحيات

| الدور | كيف يُعرف | ما يمكنه |
|---|---|---|
| زائر / عميل | بدون دخول (`anon`) | قراءة المنيو والفروع والمناطق والمواعيد؛ إنشاء طلب (`place_order`)؛ تتبع طلب برقمه وموبايله خلال 3 أيام (`track_order`) |
| موظف طلبات | حساب Auth + `staff_profiles.role = agent` (فرع واحد أو كل الفروع) | قراءة طلبات فرعه؛ نقل الحالة والإلغاء (`set_order_status`)؛ رقم الفاتورة (`set_pos_invoice`) |
| مدير | `staff_profiles.role = admin` | كل ما سبق + تعديل المنيو والمناطق والفروع والإعدادات وحسابات الموظفين (من قاعدة البيانات) |
| حساب Auth بلا ملف موظف | دخول صحيح بلا `staff_profiles` | يُطرد من اللوحة؛ لا يقرأ أي طلب |

الحسابات الحالية على المشروع الحقيقي: مدير واحد. لا يوجد حساب موظف طلبات بعد.

## الوظائف التي تحتاج حسابات مختلفة

- تجربة العميل كاملة: بلا حساب.
- لوحة الكول سنتر (نقل الحالة، الإلغاء، الفاتورة، الفلاتر، التحديث اللحظي): حساب موظف.
- قيود الفرع الواحد: حساب موظف مربوط بفرع.
- إضافة وحذف المناطق: حساب مدير؛ ومحاولة نفس الشيء بحساب موظف عادي (يجب أن تُرفض).
